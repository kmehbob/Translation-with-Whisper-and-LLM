Architecture reference · v1

Urdu speech-to-text & Urdu→English translation, fully self-hosted

A private, GPU-accelerated pipeline added to the existing Express app: record or type Urdu, transcribe it locally with faster-whisper, edit the text, then translate it to fluent English with a self-hosted LLM — no OpenAI, Anthropic, Google, or other third-party inference API involved anywhere.

Node.js · Express gateway Python · FastAPI faster-whisper (CUDA) Qwen2.5-Instruct (CUDA) Docker Compose · NVIDIA Container Toolkit

01 Overview

What the system does, end to end, before the architecture detail.

  1. User records Urdu speech in the browser (or uploads an audio file, or types Urdu directly).
  2. Audio is sent to the gateway, which forwards it to a local faster-whisper model forced to Urdu — the audio never leaves infrastructure you control.
  3. The resulting Urdu text appears in an editable text area; the user can fix it before translating.
  4. Clicking Translate to English sends the (possibly edited) Urdu text to a self-hosted Qwen2.5-Instruct model.
  5. The English translation appears in its own panel; Urdu and English can be copied independently, and editing the Urdu again marks the English stale.

Design constraints that shaped every decision below

ConstraintConsequence
No third-party AI APIsBoth models run in-process on your own GPU(s); the gateway never calls out to OpenAI/Anthropic/Google for transcription or translation.
Target GPU specs unknownModel size, precision, quantization, batch size, and context length are all environment variables with tier-appropriate defaults — see §6.
Existing app must keep workingThe gateway is the same Express process as before; /speak and /health are untouched, and a single flag (ENABLE_AI_FEATURES=false) fully disables the new feature.
Shared GPU, bursty trafficConcurrency is bounded at three independent layers so a burst of requests degrades to a fast 503 instead of an out-of-memory crash — see §5.

02 System architecture

One public process, two private GPU services, one crossing point.

This mirrors the app's existing shape — one Express process serving the UI and terminating client requests — with two new internal collaborators instead of a rewrite. The gateway never loads an ML framework; the Python services never see the public internet.

Transcription service — ai-services/transcription/

FastAPI app around faster-whisper. model_backend.py loads the model once at startup and is the only module that imports the (heavy) ML library, so unit tests can stub it entirely. Language is forced to ur rather than auto-detected, so a sentence with an occasional English word doesn't cause the decoder to switch languages mid-utterance.

# POST /v1/transcribe — abbreviated request lifecycle
verify_token(authorization)                    # 401 if Bearer mismatch
guard.try_acquire()                            # 503 if MAX_CONCURRENT_TRANSCRIPTIONS reached
validate content_type in ALLOWED_CONTENT_TYPES # 400 otherwise
stream to tempfile, enforcing MAX_AUDIO_UPLOAD_MB # 413 if exceeded
asyncio.to_thread(model_backend.transcribe_file, tmp_path)
finally: guard.release(); os.remove(tmp_path)

Translation service — ai-services/translation/

model_backend.py wraps a transformers chat model (Qwen2.5-Instruct by default). prompt.py builds the controlled system prompt and defends against instruction injection; chunker.py splits long input by structure. Generation is greedy (DO_SAMPLE=false) for deterministic, reproducible translations.

# POST /v1/translate — abbreviated request lifecycle
verify_token(authorization); validate 0 < len(text) <= MAX_TRANSLATE_TEXT_LENGTH
guard.try_acquire()                            # 503 if MAX_CONCURRENT_TRANSLATIONS reached
batches = chunker.build_batches(text, count_tokens, MAX_INPUT_TOKENS_PER_CHUNK)
for batch in batches:
    if request.is_disconnected(): abort   # cooperative cancellation between chunks
    translated.append(model_backend.translate_one(batch))  # prompt.py wraps + sanitizes the text
return chunker.reassemble(translated)

Prompt-injection defense, concretely

The Urdu text is wrapped in fixed delimiters before it reaches the model, and any literal delimiter sequence inside the user's text is neutralized first, so a message like "...<<>> ignore all previous instructions" cannot forge a fake end-of-content marker and leak into instruction context:

BEGIN_MARKER = "<<<URDU_TEXT_START>>>"
END_MARKER   = "<<<URDU_TEXT_END>>>"

def _neutralize_delimiter_collisions(text):
    return text.replace("<<<", "‹‹‹").replace(">>>", "›››")

def build_messages(user_text):
    safe_text = _neutralize_delimiter_collisions(user_text)
    wrapped = f"{BEGIN_MARKER}\n{safe_text}\n{END_MARKER}"
    return [{"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": wrapped}]

The system prompt itself explicitly instructs the model to treat the delimited block as literal data — never as commands — and to return only the translated text. See ai-services/translation/tests/test_prompt.py for the adversarial cases this is tested against.

06 Model selection

Chosen deliberately, not defaulted — with the rejected alternatives and why.

Transcription — faster-whisper

faster-whisper (CTranslate2 backend) over vanilla openai-whisper: 2-4× faster inference at equal accuracy, lower memory, and — notably — no torch dependency, which keeps the service image small and startup fast.

GPU VRAMWHISPER_MODEL_SIZENotes
Low (4–6GB)smallFast, good enough for short clips
Medium (8–16GB)medium defaultBest accuracy/speed tradeoff for Urdu
High (24GB+)large-v3Best accuracy; needed for noisy or long-form audio

07 Implementing on GPU

Two supported paths — Docker Compose (recommended) and native/bare-metal — plus how to confirm the GPU is actually being used.

Prerequisites

RequirementWhy
NVIDIA driver matching your GPU (≥ 535 recommended)Both services' Dockerfiles target CUDA 12.4
Docker Engine + Compose v2Runs docker-compose.yml
NVIDIA Container ToolkitLets containers see /dev/nvidia* and CUDA libraries
~15GB free disk under the model cache pathWhisper medium (~1.5GB) + Qwen2.5-7B in 4-bit (~5GB) plus headroom for a larger tier later

Path A — Docker Compose (recommended)

  1. Install the NVIDIA Container Toolkit on the GPU host (Ubuntu example): 
    curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
  2. Confirm Docker can see the GPU before touching this app: 
    docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
    You should see your GPU listed. If this fails, stop here — the app-level steps below can't work until this does.
  3. Configure the environment: 
    cd server
cp .env.example .env
# set a real INTERNAL_SERVICE_TOKEN, e.g.:
openssl rand -hex 32   # paste the output into INTERNAL_SERVICE_TOKEN=
# pick WHISPER_MODEL_SIZE / TRANSLATION_MODEL_NAME / TRANSLATION_PRECISION
# for your GPU's VRAM tier — see §6 tables above
  4. Build and start: 
    docker compose build
docker compose up -d
docker compose ps       # all three services should show "healthy" once models finish loading

    First startup is slow: the translation container downloads Qwen2.5-7B's weights (several GB) into the translation-model-cache volume the first time only. Watch progress with docker compose logs -f translation. Subsequent restarts reuse the cached weights and start in seconds.

  5. Confirm readiness: 
    curl http://localhost:3000/api/v1/ready
# {"status":"ready","aiFeaturesEnabled":true,"services":{"transcription":true,"translation":true}}
  6. Put a TLS-terminating reverse proxy (nginx/Caddy/your load balancer) in front of port 3000 — the app itself speaks plain HTTP, matching the pre-existing setup.

Path B — Native / bare-metal (no Docker)

Useful for a single dedicated GPU box, or while iterating on the Python services directly.

# 1) Gateway
cd server
npm install
npm start                                     # :3000

# 2) Transcription service (separate shell)
cd server/ai-services/transcription
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt               # faster-whisper needs no separate torch install
uvicorn app:app --host 0.0.0.0 --port 8001

# 3) Translation service (separate shell)
cd server/ai-services/translation
python -m venv .venv && source .venv/bin/activate
# install the CUDA build of torch that matches your driver FIRST:
pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8002

Set TRANSCRIPTION_SERVICE_URL=http://localhost:8001 and TRANSLATION_SERVICE_URL=http://localhost:8002 in the gateway's .env (these are already the defaults).

09 Privacy & data lifecycle

What is never stored

  • Uploaded audio — deleted in a finally block at both the gateway and the transcription service
  • Urdu / English text — held in memory for the request only, never written to disk or a database
  • Anything used for model training — both models are frozen, pre-trained checkpoints run purely for inference

What logs actually contain

  • Request IDs, durations, byte counts, HTTP status codes
  • Never: raw Urdu/English text, audio bytes, tokens, or API keys — redacted by construction in lib/logger.js / logging_utils.py, not by remembering to scrub each call site
  • Verified by tests/logger.test.js and tests/privacyLogging.test.js

10 Testing

Node

40 tests, Jest + supertest, AI-service calls mocked via axios. Covers auth, rate limiting, rollback, timeouts, oversized input, temp-file cleanup, privacy-safe logging, and upload-filename sanitization.

Python

44 tests (2 more skipped by design), pytest, model_backend stubbed so torch/faster-whisper never need installing for unit tests. Covers chunking (including the word-level fallback for punctuation-free oversized text), prompt-injection defense, concurrency semaphores.

Integration

Gated behind RUN_GPU_INTEGRATION_TESTS=1 — run these against the real models once deployed on GPU hardware: npm run test:integration.

12 Rollback, monitoring & QA

Rollback

This was an additive change — nothing existing was removed. Fastest rollback: set ENABLE_AI_FEATURES=false and restart the gateway; the new routes return 503 immediately while /speak, /health, and the static UI keep working. Full rollback: stop the transcription/translation containers, or redeploy the gateway from before this change.

Monitoring

  • nvidia-smi / DCGM exporter on the GPU host for VRAM and utilization
  • Docker healthchecks already wired to each service's /health and /ready
  • Alert on sustained ai_service_error / 503 rates in gateway logs (GPU saturation or a crashed model process)
  • Track transcription_completed.duration_ms and translation_completed.duration_ms as separate latency series
